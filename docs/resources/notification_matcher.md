# Resource: proxmox_notification_matcher

Manages a Proxmox VE notification matcher (`/cluster/notifications/matchers`). Matchers route notifications to one or more targets based on metadata, severity, and calendar conditions. Requires `Mapping.Modify` on `/mapping/notifications`. Available since PVE 8.1.

## Example Usage

```terraform
resource "proxmox_notification_endpoint_sendmail" "ops" {
  name   = "ops-sendmail"
  mailto = ["ops@example.com"]
}

resource "proxmox_notification_matcher" "backup_failures" {
  name           = "backup-failures"
  target         = [proxmox_notification_endpoint_sendmail.ops.name]
  match_field    = ["exact:type=vzdump"]
  match_severity = ["error", "warning"]
  match_calendar = ["mon..fri 09:00-17:00"]
  mode           = "all"
  comment        = "Route backup failures to ops during business hours"
}
```

## Schema

### Required

- `name` (String) The unique name of the matcher. Used as the resource ID in PVE.

### Optional

- `comment` (String) Free-form comment.
- `disable` (Boolean) Whether the matcher is disabled. Defaults to `false`.
- `invert_match` (Boolean) Whether to invert the result of the entire matcher. Defaults to `false`.
- `match_calendar` (Set of String) Match notification timestamps. Each entry is a systemd-style calendar event spec.
- `match_field` (Set of String) Match notification metadata fields. Each entry is `(exact|regex):<field>=<value>` (e.g., `exact:type=vzdump`).
- `match_severity` (Set of String) Match notification severities (e.g., `info`, `notice`, `warning`, `error`, `unknown`).
- `mode` (String) How multiple match conditions are combined: `all` (AND) or `any` (OR). Defaults to `all`.
- `target` (Set of String) Names of notification targets to invoke when this matcher matches.

### Read-Only

- `digest` (String) SHA-1 digest of the notifications configuration, used for optimistic locking on update.
- `id` (String) The unique identifier of this resource.
- `origin` (String) Origin of this entry: `user-created`, `builtin`, or `modified-builtin`.
